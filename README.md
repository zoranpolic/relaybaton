# relaybaton

[![CI](https://github.com/zoranpolic/relaybaton/actions/workflows/ci.yml/badge.svg)](https://github.com/zoranpolic/relaybaton/actions/workflows/ci.yml)
![Python 3.11+](https://img.shields.io/badge/python-3.11%2B-blue)
![Dependencies: none](https://img.shields.io/badge/runtime%20dependencies-0-brightgreen)
[![License: MIT](https://img.shields.io/badge/license-MIT-green)](LICENSE)

**Pass the baton between AI coding agents.**

If you use more than one AI coding agent (Claude Code, Codex, Copilot, Gemini) on the same
repository, three things go wrong sooner or later:

1. **Instructions drift.** `CLAUDE.md` says one thing, `.github/copilot-instructions.md` says
   another, and nobody remembers which file is current.
2. **Handoffs go quiet.** Agents leave notes for each other in a shared file until one day they
   don't, and the log *looks* fine because its modification time keeps changing.
3. **Agents step on each other's work.** One agent "helpfully" rewrites a file another agent, or a
   person, owns.

`baton` is a small, dependency-free CLI that fixes all three, and fails loudly in CI when they come
back.

```text
$ baton doctor
relaybaton 0.1.0 in /work/my-service
instructions:
  ok        CLAUDE.md
  ok        .github/copilot-instructions.md
  DRIFTED   GEMINI.md
handoff log:
  STALE     HANDOFF.md: newest entry 2026-09-30, 58 day(s) old (limit 14), 41 entries
2 problem(s) found
```

## Install

```bash
pip install git+https://github.com/zoranpolic/relaybaton
```

Python 3.11 or newer. No runtime dependencies.

## Quick start

```bash
baton init        # creates baton.toml, AGENTS.md and HANDOFF.md
$EDITOR AGENTS.md # write your project's rules once
baton sync        # generates CLAUDE.md, GEMINI.md, .github/copilot-instructions.md
baton check       # exits 1 if any of them is missing or out of date
```

## What it does

### 1. One source of instructions: `baton sync` and `baton check`

You edit **`AGENTS.md`**, nothing else. `baton sync` writes each agent's file from it, with a
header that names the source and a content hash:

```markdown
<!-- relaybaton:generated source=AGENTS.md agent=claude sha256=3ee0fd2b1c3b -->
<!-- Do not edit this file. Edit AGENTS.md and run `baton sync`. -->
```

Need something only one agent should read? Put it in `AGENTS.<agent>.md` (for example
`AGENTS.claude.md`) and it is appended to that agent's file only.

`baton check` compares every target with what it should be and reports `MISSING`, `DRIFTED`
(someone edited a generated file, or the source changed) or `UNMANAGED` (a hand-written file is in
the way). Add `--diff` to see exactly what changed.

`sync` never overwrites a hand-written file unless you pass `--force`, so trying it on an existing
repository is safe.

### 2. An honest handoff log: `baton handoff`

```bash
baton handoff add --author claude --to codex --subject release "Tests pass on main. Please cut v0.1.0."
baton handoff list
baton handoff status          # exits 1 when the newest entry is older than max_age_days
```

Entries are dated Markdown headings, newest first, so people and agents can both read and write the
file:

```markdown
### 2026-11-27 — claude → codex (release)

Tests pass on main. Please cut v0.1.0.
```

`status` judges freshness from the **newest dated heading, never the file's modification time**.
Sync clients and editors rewrite mtimes without adding a word, which is exactly how a handoff channel
can be dead for months while every timestamp says it is healthy.

### 3. File ownership: `baton guard`

```toml
[ownership]
"*-codex.*" = "codex"
"docs/legal/*" = "human"
```

```text
$ baton guard --agent claude --base origin/main
  BLOCKED   notes/plan-codex.md is owned by codex, not claude
1 file(s) belong to another agent: hand them off instead
```

`guard` looks at everything changed on the branch (committed since `--base`, staged, unstaged and
untracked) and fails if the agent touched a file someone else owns. Run it in an agent's pre-commit
hook or in CI on the agent's pull requests.

## Use it in CI

As a GitHub Action:

```yaml
- uses: actions/checkout@v7
- uses: zoranpolic/relaybaton@v0.1.0
  with:
    command: check            # or: doctor, "handoff status", "guard --agent codex --base origin/main"
```

As a [pre-commit](https://pre-commit.com) hook:

```yaml
- repo: https://github.com/zoranpolic/relaybaton
  rev: v0.1.0
  hooks:
    - id: baton-check
```

## Configuration

`baton.toml` lives at the repository root; every command finds it from any subdirectory.

| Key | Default | Meaning |
|---|---|---|
| `source` | `"AGENTS.md"` | The one file you edit. |
| `[targets]` | claude, gemini, copilot | Agent name → generated file path. |
| `[handoff] file` | `"HANDOFF.md"` | The handoff log. |
| `[handoff] max_age_days` | `14` | `status` fails at this age. |
| `[ownership]` | empty | Glob → owning agent. Globs without `/` match the file name anywhere. |

Exit codes: `0` all good, `1` a check found a problem, `2` usage or configuration error.

## Design choices

- **No runtime dependencies.** Standard library only (`tomllib`, `argparse`, `subprocess`), so
  adding it to a pipeline adds no supply-chain surface.
- **Paths are confined to the repository.** A config copied from elsewhere cannot make `sync` write
  to `../../.bashrc`; absolute paths and `..` escapes are rejected before anything is written.
- **Git is called with fixed argument lists**, never through a shell.
- **Generated files are marked**, so `check` can tell "out of date" from "a person wrote this" and
  never destroys the latter.
- **The CI for this repository uses its own action** and pins every third-party action to a full
  commit SHA with read-only permissions.

## How it compares

[`AGENTS.md`](https://agents.md) is becoming the shared convention for agent instructions, and
several tools already copy one rules file into each agent's format. relaybaton does that too, but
its focus is the part those tools leave out: **coordination over time**, meaning a handoff log you
can trust and ownership rules an agent cannot quietly cross.

## Background

relaybaton grew out of running Claude Code, Codex and chat assistants side by side on real work for
months, with shared instruction files, handoff notes between agents, and a watchdog for when one of
them stalled. Every check here exists because its absence caused a real failure.
